# Установка postmarketOS с Phosh на Realme 10 4G (RMX3630)

Статус инструкции: developer preview, 23 июля 2026 года. Порт один раз
установлен и проверен на реальном RMX3630. Это пока не официальный порт
postmarketOS и не готовая потребительская прошивка.

## Что получится

Телефон загружает postmarketOS v26.06 с Phosh из слота A. Корневая файловая
система ext4 занимает весь бывший раздел `userdata`: на проверенном аппарате
это около 220 ГиБ доступного пространства.

Работают:

- дисплей 1080x2400, 60 Гц;
- сенсорный экран;
- кнопки громкости;
- кнопка питания через программное гашение и включение подсветки;
- аппаратное ускорение Mali-G57 MC2 через Mesa/Panfrost;
- встроенный динамик;
- Wi-Fi и NetworkManager;
- экранная клавиатура Squeekboard;
- USB-сеть RNDIS, SSH и отладочная shell.

Не работают или не проверены полностью:

- процент заряда и состояние зарядки;
- нормальный suspend/resume и стандартный DRM DPMS;
- микрофоны и гарнитура;
- камеры;
- сотовая связь, звонки и мобильный интернет;
- Bluetooth, GPS, NFC, фонарик и большинство датчиков.

Это Linux-планшет для экспериментов, а не готовая замена основному телефону.

## Поддерживаемая модель

Инструкция предназначена только для:

- Realme 10 4G;
- код модели `RMX3630`;
- SoC MediaTek MT6789 / Helio G99;
- Oplus project `2269E`.

Она не подходит для Realme 10 5G и других аппаратов с похожим названием.
Перед прошивкой сверьте модель в Android и аппаратную строку, которую выводит
UnlockTool. Если там не `RMX3630`, `MT6789` и `2269E`, остановитесь.

## Главные предупреждения

1. Установка уничтожает Android и все пользовательские данные в `userdata`.
2. Слот B не является надёжным способом вернуться в Android: оба слота Android
   используют один и тот же `userdata`, который после установки содержит ext4.
3. Обычный fastboot на этом аппарате может отвечать `the serial is not match`
   или `fastboot_unlock_verify_fail`. Проверенная прошивка выполнялась через
   MediaTek Preloader и UnlockTool.
4. Надпись `Orange State` после разблокировки загрузчика ожидаема.
5. Никогда не используйте `Format All`, `Re-Partition` и стирание NVRAM.
6. Не прошивайте `preloader`, GPT и калибровочные разделы из чужого дампа.
7. Не загружайте в Linux модуль `oplus_chg.ko`: на проверенном ядре он вызывает
   воспроизводимый kernel panic.

Продолжайте только при наличии полного собственного дампа и рабочего способа
подключиться к Preloader.

## Что должно быть в релизном комплекте

Нормальный комплект для установки должен содержать:

```text
rootfs.img                  ext4-образ postmarketOS/Phosh для userdata
boot_a.img                  ядро Realme и RMX3630 initramfs
misc.img                    выбор слота A
RMX3630-pmos-only-scatter.txt
SHA256SUMS
```

Scatter-файл релиза обязан разрешать запись только трёх разделов:
`userdata`, `boot_a` и `misc`. Если в списке автоматически отмечены
`preloader`, `pgpt`, `super`, `nvram`, `nvdata`, `persist` или любые другие
разделы, не начинайте прошивку.

Проверенные образы загрузочной цепочки v28 имеют такие суммы:

```text
4799267c116f46753822a89a701e4a41035d347bd4e157718c3f4fe05115afd1  boot_a.img
9ef62d6050c5eb9aa525051fcdbcfaf8d8f7d5f0942e85c835f1b024590f2982  misc.img
```

Сумму `rootfs.img` нужно брать из `SHA256SUMS` конкретного релиза. Маленький
образ `postmarketos-v26.06-live-usb-root-v26-556m.img` из рабочего каталога —
это старое диагностическое окружение, а не полноценная система с Phosh.

Текущий файл `out/unlocktool-pmos-v28/MT6789_Android_scatter.txt` также не
является безопасным публичным scatter: он получен из полной стоковой разметки
и содержит другие разделы с `is_download: true`. Использовать его можно только
вручную сняв все лишние галочки.

### Проверка сумм в PowerShell

Из каталога с релизом:

```powershell
Get-FileHash .\boot_a.img -Algorithm SHA256
Get-FileHash .\misc.img -Algorithm SHA256
Get-FileHash .\rootfs.img -Algorithm SHA256
```

Все три значения должны в точности совпасть с `SHA256SUMS`.

## Необходимые инструменты

- Windows 10 или 11;
- качественный USB-кабель и прямой порт компьютера;
- драйвер MediaTek PreLoader USB VCOM;
- действующая лицензия UnlockTool с поддержкой OPPO/Realme/OnePlus MTK;
- не менее 50% заряда аккумулятора;
- около 10 ГиБ свободного места для релиза и резервных копий, либо значительно
  больше для полного дампа `super` и `userdata`;
- WSL2 Ubuntu с `dd`, `sha256sum` и `netcat-openbsd` — только для проверенного
  потокового способа из приложения ниже.

Fastbootd для основной процедуры не нужен.

## 1. Сделать резервную копию

В UnlockTool выберите MediaTek, профиль авторизации
`OPPO/REALME/ONEPLUS [3]` и точную модель/платформу, определённую программой.

Сохраните полный дамп UFS. Если полный дамп невозможен, обязательно сохраните
как минимум:

```text
preloader, pgpt, misc
boot_a, boot_b
vendor_boot_a, vendor_boot_b
dtbo_a, dtbo_b
vbmeta_a, vbmeta_b
vbmeta_system_a, vbmeta_system_b
vbmeta_vendor_a, vbmeta_vendor_b
super
nvram, nvdata, nvcfg, persist
proinfo, otp, seccfg, param, ocdt, oplus_custom
```

Если нужны данные Android, отдельно скопируйте их обычным способом. Образ
`userdata` может быть зашифрован и сам по себе не заменяет резервную копию
фотографий и документов.

Проверьте, что дампы не нулевого размера, и сделайте для них SHA-256. Храните
копию не на том же диске, где лежит рабочий каталог.

## 2. Разблокировать загрузчик

На проверенном RMX3630 штатный fastboot не принимал обычную команду unlock.
Рабочим оказался пункт UnlockTool `PERM|UNLOCK BL` через Preloader.

Названия кнопок меняются между версиями UnlockTool, поэтому ориентируйтесь на
операцию постоянной разблокировки bootloader для RMX3630. Не выбирайте FRP,
Format Data, Format All или Re-Partition.

После разблокировки телефон показывает `Orange State`. Это предупреждение о
разблокированном загрузчике, а не ошибка postmarketOS.

## 3. Подключить телефон к Preloader

1. Полностью выключите телефон.
2. В UnlockTool заранее запустите нужную операцию и дождитесь ожидания порта.
3. Для режима Preloader подключите выключенный телефон без зажатых кнопок.
4. В диспетчере устройств на несколько секунд должен появиться
   `MediaTek PreLoader USB VCOM (Android)`.

Если аппарат находится в цикле перезагрузки, удерживайте Power примерно
10 секунд, дождитесь отключения и переподключите кабель. BROM с кнопками
громкости нужен только если операция прямо требует BROM. Разбирать телефон и
замыкать test point для этой установки не требуется.

Если UnlockTool пишет `Handshake failed`, проверьте другой прямой USB-порт,
кабель, драйвер VCOM и отсутствие другой программы, удерживающей COM-порт.

## 4. Записать систему через UnlockTool

Этот вариант является целевым для публичного релиза. На первом портированном
аппарате `userdata` записывалась из временного Linux по USB, поэтому прямую
запись `rootfs.img` через UnlockTool следует считать ещё не проверенной на
втором телефоне. Не используйте её без собственного дампа.

1. Откройте безопасный `RMX3630-pmos-only-scatter.txt` из релиза.
2. Убедитесь, что накопитель определён как UFS, а платформа как MT6789.
3. Отключите `Format All`, `Re-Partition` и все дополнительные erase-операции.
4. Оставьте отмеченными ровно три строки:

   | Раздел | Файл | Ожидаемый размер раздела |
   |---|---|---:|
   | `userdata` | `rootfs.img` | зависит от версии телефона |
   | `boot_a` | `boot_a.img` | 64 МиБ |
   | `misc` | `misc.img` | 512 КиБ |

5. Сначала запишите `userdata`, затем `boot_a`, и последним `misc`. Если
   программа выполняет все три записи одной операцией, проверьте список ещё
   раз перед нажатием Flash.
6. Дождитесь успешного завершения и только затем отключите кабель.
7. Если UnlockTool имеет отдельную команду `SET BOOT SLOT`, выберите A. В
   журнале должно появиться `Set boot slot A... OK`.

Не записывайте Linux в `super`, `system_a`, `my_preload_b` или случайный
`oplusreserve*`. Финальная система использует обычный физический `userdata`.

## 5. Первый запуск

Включите телефон обычной кнопкой Power. Последовательность примерно такая:

1. предупреждение `Orange State`;
2. логотип Realme;
3. возможные краткие полосы во время инициализации vendor DRM;
4. экран блокировки Phosh.

Первый запуск может занять несколько минут. Не переключайте слот после одного
медленного старта. Если аппарат шесть раз подряд возвращается в recovery или
слот B, это уже ошибка: проверьте `misc`, выбор A и контрольную сумму rootfs.

После загрузки проверьте объём корня:

```sh
findmnt /
df -h /
```

Если образ сохранил свой первоначальный размер, ext4 обычно можно расширить
до всего `userdata` прямо после первой загрузки:

```sh
sudo resize2fs /dev/sdc71
df -h /
```

В загрузочном/сервисном окружении, где раздел не смонтирован, можно сначала
дополнительно проверить файловую систему:

```sh
e2fsck -pf /dev/sdc71
resize2fs /dev/sdc71
```

Увеличение ext4 онлайн поддерживается; уменьшать смонтированный корень нельзя.

## 6. Доступ по USB и первичная защита

Рабочая сборка создаёт USB RNDIS-сеть:

```text
телефон: 172.16.42.1
компьютер: 172.16.42.2
```

Проверка из PowerShell:

```powershell
ping 172.16.42.1
ssh user@172.16.42.1
```

Пароль задаётся при сборке rootfs и должен быть указан в примечаниях к
релизу. Сразу смените пароли:

```sh
passwd
sudo passwd root
```

Прототип также запускает неаутентифицированную root-shell на TCP 23:

```powershell
telnet 172.16.42.1 23
```

Она предназначена только для bring-up по изолированному USB-линку. Для
повседневного использования её нужно удалить из
`/sbin/rmx3630-systemd-wrapper`, оставить SSH и пересобрать `boot_a/rootfs`.
До этого не подключайте USB-интерфейс к мостам, общей сети или Интернету.

Также публичный rootfs нельзя распространять с одинаковыми SSH host keys.
Ключи должны генерироваться на первом запуске.

## 7. Проверка после установки

Выполните по SSH:

```sh
systemctl --failed
systemctl is-active \
  rmx3630-audio rmx3630-gpu rmx3630-input rmx3630-softpower \
  rmx3630-pulse-sink rmx3630-phosh-direct rmx3630-wifi \
  NetworkManager sshd

findmnt -no SOURCE,FSTYPE,SIZE,AVAIL /
ip -br address show usb0
ip -br address show wlan0
cat /sys/class/drm/renderD128/device/uevent
```

Ожидается `/dev/sdc71`, ext4, активные сервисы и `DRIVER=panfrost`.

Проверка OpenGL:

```sh
sudo -u user env \
  XDG_RUNTIME_DIR=/run/user/10000 \
  WAYLAND_DISPLAY=wayland-0 \
  eglinfo -B
```

Renderer должен содержать `Mali-G57 MC2 (Panfrost)`, а не `llvmpipe`.

## 8. Wi-Fi

Через интерфейс Phosh выберите сеть и введите пароль экранной клавиатурой.
Из SSH то же самое можно сделать так:

```sh
nmcli radio wifi on
nmcli device wifi list
nmcli device wifi connect 'ИМЯ_СЕТИ' password 'ПАРОЛЬ'
```

Диагностика:

```sh
systemctl status rmx3630-wifi --no-pager
journalctl -b -u rmx3630-wifi -u NetworkManager --no-pager
ip link show wlan0
```

## 9. Особенности управления питанием

Стандартное выключение DRM-коннектора не пробуждает vendor AMOLED. Поэтому
кнопка Power обрабатывается сервисом `rmx3630-softpower`: он ставит яркость в
0, блокирует события тача, а следующим нажатием возвращает яркость.

Это не настоящий suspend. Телефон продолжает работать и расходовать энергию.
Уровень включённой яркости можно задать числом от 1 до 2047:

```sh
echo 1024 | sudo tee /etc/rmx3630-softpower-brightness
sudo systemctl restart rmx3630-softpower
```

## Типовые проблемы

### `the serial is not match` / `fastboot_unlock_verify_fail`

Это ограничение загрузчика Realme, обнаруженное и на проверенном устройстве.
Не пытайтесь бесконечно войти в fastbootd кнопками. Используйте собственный
дамп и авторизованный Preloader-доступ UnlockTool.

### Только `Orange State` и логотип Realme

Подождите до трёх минут. Затем проверьте:

- записан ли полный `rootfs.img` в `userdata`;
- совпадает ли его SHA-256;
- выбран ли слот A;
- соответствует ли `boot_a.img` этому rootfs;
- не попал ли образ в `boot_b` вместо `boot_a`.

### Телефон уходит в recovery или обратно в B

Повторно выполните `SET BOOT SLOT A` и запишите `misc.img`. Если `userdata`
осталась Android/F2FS либо образ повреждён, initramfs не сможет смонтировать
корень и загрузка также не продолжится.

### Экран чёрный, но USB отвечает

```sh
systemctl status rmx3630-gpu rmx3630-phosh-direct --no-pager
journalctl -b -u rmx3630-gpu -u rmx3630-phosh-direct --no-pager
cat /run/rmx3630-gpu.log
cat /run/rmx3630-phosh.log
```

Не переключайте Phosh обратно на pixman, если Panfrost успешно создал
`/dev/dri/renderD128`. Не запускайте обычный DPMS-off вручную: панель может не
включиться до перезагрузки.

### Не отображается аккумулятор

Это известное ограничение. Не пытайтесь исправить его загрузкой
`oplus_chg.ko`: текущая версия вызывает падение ядра.

## Возврат на Android

Надёжное восстановление требует собственного полного дампа или полной
официальной прошивки именно для RMX3630 и вашей ревизии.

Минимально нужно:

1. вернуть стоковые `boot_a`/`boot_b`, соответствующие им `vendor_boot`,
   `dtbo` и все `vbmeta`;
2. вернуть исходный `misc` или корректно выбрать стоковый слот;
3. восстановить `super`, если он менялся во время экспериментов;
4. стереть/переформатировать `userdata` в ожидаемый Android формат — Linux
   ext4 несовместим с прежним зашифрованным `/data`;
5. только после успешной стоковой загрузки решать вопрос с повторной
   блокировкой bootloader.

Не блокируйте загрузчик при смешанном наборе Linux/Android-разделов. Не
восстанавливайте чужие `nvram`, `nvdata`, `persist`, `proinfo`, `otp`,
`seccfg`, `ocdt` и `param`.

## Приложение A: как был записан первый аппарат

Этот раздел нужен для воспроизводимости порта. Он предполагает, что телефон
уже загружен во временное RMX3630 Linux-окружение с USB RNDIS и root-shell, а
`/dev/sdc71` не смонтирован. Само временное окружение ранних версий размещалось
в динамическом разделе внутри `super`; слепо повторять его физическое смещение
на другой прошивке нельзя.

На телефоне запускается приёмник:

```sh
findmnt /dev/sdc71 && exit 1
nc -l -p 9000 | dd of=/dev/sdc71 bs=4194304 conv=fsync
sync
```

В WSL2 Ubuntu:

```sh
img=/path/to/rootfs.img
sha256sum "$img"
dd if="$img" bs=4M status=progress | nc -N -w 10 172.16.42.1 9000
```

Размер образа должен быть кратен 4096. Для поблочной проверки на телефоне:

```sh
# Подставить число: размер rootfs.img в байтах / 4096
dd if=/dev/sdc71 bs=4096 count=BLOCK_COUNT | sha256sum
```

Сумма обязана совпасть с локальной. Затем, пока раздел не смонтирован:

```sh
e2fsck -pf /dev/sdc71
resize2fs /dev/sdc71
```

На первом аппарате использовались следующие физические устройства UFS:

```text
/dev/sdc1   misc       512 КиБ
/dev/sdc34  boot_a      64 МиБ
/dev/sdc70  super      9,5 ГиБ
/dev/sdc71  userdata   около 227 ГиБ физически
```

Имена подтверждены на одном RMX3630, но перед любой записью их нужно заново
сверить с GPT/`partitions.txt` конкретного телефона.

## Приложение B: сборка rootfs для разработчика

Проверенный образ создавался pmbootstrap 3.11.1 из ветки postmarketOS v26.06,
с systemd и Phosh. Локальные порты находятся в `pmaports/` этого проекта.

Использованная команда имела вид:

```sh
./pmbootstrap.py \
  -c /path/to/rmx3630-linux-port/pmaports/pmbootstrap-v2606.example.cfg \
  -p /path/to/pmaports-v2606 \
  -E 512 install \
  --split \
  --filesystem ext4 \
  --password='ВРЕМЕННЫЙ_ПАРОЛЬ' \
  --no-firewall
```

После сборки применялись RMX3630-модули, firmware, systemd units и настройки
из `rootfs/`, `out/audio-live-dvfs-disabled`, `out/panfrost-live` и
`out/wifi-live`. Перед публикацией обязательны:

- новая случайная соль и пароль либо мастер первого запуска;
- удаление готовых SSH host keys;
- отключение root-shell TCP 23;
- `e2fsck -f` и SHA-256 финального, уже не изменяемого образа;
- проверка установки на втором RMX3630 из чистого стокового состояния.

Старая локальная сборка rootfs размером 2 964 324 352 байта и SHA-256
`c6495e5e449e627501fa0475ccd9e927d548befffb863837b1461172c8fdacf3`
была создана до части live-исправлений Wi-Fi/Panfrost и не должна выдаваться
за готовый публичный релиз.
